One-minute explanation

Auditable Voting is a questionnaire system where the organiser controls who can vote, voters submit through private submission identities, and observers can check the public count.

  1. The organiser creates a questionnaire.
  2. A voter opens the invite and receives a ballot credential.
  3. The voter submits a response once.
  4. The organiser publishes the result.
  5. Observer checks accepted submissions, invalid submissions, and the final count.

Before you start

Use separate sessions

Open Organiser, Voter, and Observer in separate browser profiles, private windows, or devices.

Use one short question

A single yes/no question is enough to show the full workflow without distracting the audience.

Keep Observer visible

Observer is the proof point. It shows that the result can be read and checked from public data.

Five-minute demo

Open Organiser and publish a questionnaire

Open Organiser. Use Login if you already have an organiser identity, or use New identity for a fresh local demo identity.

Fill in Name, Description, and at least one Question prompt. When the readiness checklist is complete, click Publish questionnaire, then Open vote.

Share the General invite

In Organiser, open Invite voters. Use the General invite link or QR code.

Voters who open this link are sent to Voter and request a ballot automatically.

Open Voter and choose an identity

Open the invite in the Voter session, or open Voter directly. Open Menu.

Use Login if you already have a voter identity, or use New identity for a fresh local demo identity.

The top-right label should show the Voter identity, for example Voter dv0lu66. No email address, phone number, or password is needed for this demo.

Submit a response

The invite should open the questionnaire and request a ballot. If it shows Pending invites, click Open + request ballot.

Answer the question and click Submit response. For free-text questions, use Encrypt for organiser if the answer should not be public.

If the button is disabled, it will explain why, for example Please answer all required questions or Verifying vote request.

After submission, keep the Submission ID. You will use it in Observer.

Check the vote in Observer

Open Observer. Use Find Published Questionnaires, choose the questionnaire, then open Submitted Votes.

Match the voter's Submission ID to Observer's Response ID. Accepted submissions have no Invalid marker. Invalid submissions show a reason.

Publish and verify the result

Return to Organiser and click Close + publish results or Publish results.

Refresh Observer. Show Questionnaire Results, accepted count, invalid count, per-question results, and Submitted Votes.

Observer can also show live verified submissions before the final result is published.

Likely questions

Why not use a normal survey tool?

Normal survey tools require trust in the operator and database. Here, the important checks can be repeated independently.

Can the organiser see who voted for what?

The organiser controls who can take part. The submitted response uses a separate response identity, so the normal voter identity is not the public ballot identity. Free-text answers may still reveal personal information if the voter writes it.

Can someone vote twice?

Each ballot credential can be accepted once. Duplicate or invalid submissions are rejected and the reason is shown.

What should the voter check?

The voter keeps the Submission ID. Observer shows the same value as Response ID, alongside the public Submittor identity and any invalid reason.

Is this ready for official elections?

No. Treat it as experimental infrastructure. It needs independent review before high-stakes use.

How it differs from a normal questionnaire

Question Traditional online questionnaire Auditable Voting
Was my response recorded? Trust required Check the public submission
Was my response altered? Trust required Compare the published record
Was the result calculated correctly? Trust required Anyone can verify it
Can the organiser secretly change results? Difficult to detect Publicly detectable

Privacy model

Identity

The submitted response is linked to a private submission identity, not the voter's normal identity or real-world identity.

Public record

Responses can be audited and results can be verified. Personal information is not required. Free-text answers can be encrypted for the organiser when configured.

Limits to state clearly

  • This is a working prototype, not a production election service.
  • Public relay reliability can affect timing.
  • Private keys stay in the browser, so device handling matters.
  • The cryptographic and protocol design should be independently reviewed before serious deployment.
