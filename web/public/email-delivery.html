Send resident invitations by email

The website creates registered single-use invitation links. Email sending runs separately on the trusted coordinator machine. Selecting SMTP2GO does not send anything.

  1. Publish the questionnaire. Configure/check the Guardian, or keep the organiser browser open and connected to process requests.
  2. In Voters, import one resident CSV, generate missing invitations and download the private email batch. Do not generate a replacement batch after reloading: restore the saved JSON batch with the original organiser state.
  3. Move the batch outside the repository and public folders. Keep its directory private (mode 700) and the batch/password files mode 600.
  4. Check SMTP2GO usage. Configure the current UTC SMTP_QUOTA_MONTH and verified SMTP_MONTHLY_BASELINE, including tests and all sends outside the ledger.
  5. Validate using the coordinator CLI below. Add --send only with recipient authorisation.
  6. Import the new JSON results into Voters. Monitor redemption and blind-credential issuance separately.

Coordinator command

Install web dependencies, including dev dependencies, then run from web/. Provision SMTP_PASSWORD_FILE privately, or use the default ~/.config/auditable-voting/smtp-password. Never paste credentials into the website.

node scripts/otp-send-email.mjs \
  --batch PRIVATE_DIR/private-invitations.json \
  --ledger PRIVATE_DIR/ledger.json \
  --results PRIVATE_DIR/results-001.json

Without --send, this is a dry run: no SMTP connection or email. The sender pins SMTP2GO, port 587, mandatory certificate-validated STARTTLS, user organiser, and From Auditable Voting <organiser@voting.bitsbytom.com>. The address has no receiving inbox.

Quota and recovery

Use one persistent ledger for the whole SMTP account. The local budget is 250 emails per UTC month, including prior usage and every reserved attempt. It cannot observe other senders: account-wide usage must be reconciled. Do not delete/reset the ledger to gain quota.

Accepted messages are not resent. Only confirmed pre-DATA transient failures retry, once. Uncertain outcomes and interrupted attempts require provider reconciliation, never blind retries. A failure stops the rest of the batch. Preserve locks/write remnants after crashes until the old process is stopped and evidence is checked. Results paths must be new.

What the statuses mean

  • Generated: registered invitation; no email implied.
  • Accepted by email provider: SMTP acceptance, not confirmed inbox delivery.
  • Redeemed: admission registry bound a claimant.
  • Blind credential issued: organiser issuance record exists, not proof of voting.

Links are bearer secrets. Hiding them reduces accidental exposure, not access by the coordinator. They are not anonymous ballot credentials. Email receipt proves neither eligibility nor voting.
