# Shared blind-credential core implementation plan

**Goal:** Use one compatible native/Wasm RSA blind-signature implementation without changing keys, token encoding or saved credentials.

**Architecture:** Add a small `blind-credential-core/` crate wrapping the Rust blind-RSA library family already used by the Guardian. Its public API imports existing JWKs, blinds UTF-8 message bytes, signs blinded representatives, finalises with the existing saved inverse and verifies SHA-384/PSS signatures. Browser bindings preserve hexadecimal outputs. WebCrypto remains responsible for browser key generation, retaining the existing 3072-bit parameters and JWK/key-ID formats. Guardian uses the same native API. No new ballot protocol or transport. Dependency review required stable RSA 0.10.0 and a minimal documented upstream compatibility patch; see `docs/shared-blind-credentials.md`.

1. Capture a fictional, checked-in JavaScript-generated compatibility fixture. Write failing native tests for the saved credential/request, JS-issued signatures, native roundtrips and invalid inputs. Implement bounded JWK/representative validation and checked, randomly blinded private RSA operations through the existing library, not custom RSA arithmetic.
2. Add Wasm bindings and supported build commands/artifact checks. Write a JavaScript oracle test matrix: JS blind/Rust sign/JS finalise; Rust blind/JS sign/Rust finalise; native-issued/Wasm-verified and Wasm-issued/native-verified signatures. Exercise saved inverse, UTF-8, wrong keys/messages and malformed values. Keep JavaScript oracle code in tests/tooling.
3. Switch questionnaire and simple-share browser operations to the Wasm adapter; preserve their distinct message domain separators and key IDs. Switch Guardian signing/verification to native shared-core APIs, preserving event/state shapes. Keep key generation on standard WebCrypto with unchanged parameters.
4. Run Rust native/Guardian tests, Wasm builds, TypeScript, browser compatibility tests, complete Vitest suite, existing blind-share checks and a production build. Inspect Rust dependency audit availability/results. Request two independent read-only reviews and fix demonstrated findings.
5. Document compatibility evidence, remaining security limitations and dependency-removal gate. Retain the legacy JavaScript package for the independent oracle until security/compatibility review supports removing it from production dependencies; do not claim a cryptographic audit. Preserve unrelated email/MLS work, do not send live email/Nostr messages or publish code.

Verification commands will run through the central build adapters with `/mnt/fastbuild` mounted. Generated Wasm and Rust target directories remain ignored; persistent source/fixtures stay in the checkout.
