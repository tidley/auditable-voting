    How it works

    How auditable voting works

    Anonymous voting with public verification, using blind credentials and Nostr relays.

    The short version

    This system lets an organiser confirm who is allowed to vote without learning how each person voted. Admitted voters can receive the next questionnaire invite from the organiser roster, receive a fresh blind credential for each questionnaire, submit their response from a fresh identity, and observers can recompute the result from public data.

    Technical details
    1. An organiser admits a voter or confirms that a voter is eligible.
    2. The voter requests a fresh blind ballot credential for this questionnaire.
    3. The organiser signs it without seeing the final credential.
    4. The voter submits a public ballot anonymously.
    5. Anyone can verify that accepted ballots are valid, unique, and correctly tallied.

    Purpose

    What this system is trying to do

    It separates two things that are usually hard to combine: eligibility and privacy. The organiser can confirm that a voter is allowed to participate, but should not be able to see how they voted. Observers can independently recompute the result from public data.

    Why it matters

    What problem it solves

    Most online voting systems force an uncomfortable tradeoff: either the operator can link voters to votes, or the public cannot independently verify the result. Auditable Voting tries to keep voter privacy while making the count independently checkable.

    Eligibility

    The organiser decides who may take part and issues a ballot credential only to authorised voters.

    Privacy

    The final ballot is submitted from a fresh response identity with a blind credential, not from the invited voter's normal identity.

    Roles

    Who uses it

    For voters

    • Open an invite or request ballot access.
    • Wait for a ballot credential.
    • Submit each questionnaire with a fresh blind credential, using the top questionnaire selector and Answer next when several admitted-invite questionnaires are waiting.

    For organisers

    • Create and publish a questionnaire.
    • Admit voters once, then apply that roster to later questionnaires and send the next invite.
    • Invite voters or approve requests.
    • Issue blind credentials and watch results arrive.

    For observers

    • Search by questionnaire or organiser identity.
    • Check accepted and rejected public ballots.
    • Recompute the public result stream, with optional local decryption when an organiser nsec is deliberately entered.

    Data boundaries

    What is public vs private

    Public

    • Questionnaire definitions and round state.
    • Anonymous public ballot submissions.
    • Organiser accept/reject decisions.
    • Published result summaries.

    Private or local

    • Voter and organiser signing keys.
    • Token secrets and blinding factors.
    • Unspent ballot credentials.
    • Browser-local recovery state.

    Auditability

    What observers can verify

    • Which public ballots were accepted.
    • Whether a credential was spent more than once.
    • Whether rejected ballots were rejected for deterministic reasons.
    • Whether the published tally matches the accepted public ballots.
    • Encrypted answer details when the matching organiser nsec is deliberately entered in Observer.

    Trust model

    Who has to be trusted

    The organiser is trusted to decide who may participate.

    The organiser should not learn how an eligible voter voted.

    The public does not need to trust the organiser's tally, because observers can recompute the result from public events.

    The voter must protect their local keys and browser state.

    Try it

    Run a test vote

    1. Organiser

    Open Organiser, admit voters if the same group will answer later questionnaires, set up a questionnaire, publish it, then share invite links from Voters. Applying the admitted roster sends current-questionnaire invite DMs.

    2. Voter

    Open the invite as Voter, request ballot access if needed, fill in the questionnaire, and submit.

    3. Observer

    Open Observer and search for the questionnaire ID or organiser identity to verify the public result stream. Observer refreshes the selected questionnaire automatically while the page is visible; use Refresh for an immediate reload. Encrypted answer details can be decrypted locally from Submitted Votes when the matching organiser nsec is supplied.

    Questionnaires can mix yes/no, multiple-choice, ranked-choice, and free-text questions. Ranked-choice results are counted as points, with the highest total preferred: first choice gets one point per available option, later choices count down from there, and unranked options get 0 points.

    Current status

    Current limitations

    This is experimental software. The design is intended to be auditable, but it should not be treated as production election infrastructure without independent protocol and implementation review.

    • Public relay reliability can affect delivery and discovery.
    • Browser-held secret material needs careful handling.
    • The cryptographic design needs external review before production use.
    • Large multi-organiser runs are not yet reliable on the current public relay set.
